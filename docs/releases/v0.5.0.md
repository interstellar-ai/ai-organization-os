# AI Organization OS v0.5.0

The v0.5.0 milestone introduces the first real model-backed employee while preserving AI Organization OS as the authority and audit layer.

## Highlights

- Assign explicit coding work orders from the Projects workspace.
- Require source-code `read`, `modify`, and `execute` permission before Codex starts.
- Run each coding task in a detached Git worktree with Codex `workspace-write` sandboxing.
- Keep push, merge, deployment, and external-service actions outside the coding executor.
- Record execution summaries, changed files, model usage, restrictions, and audit evidence.
- Manage employees, job templates, assets, policies, access requests, temporary grants, goals, tasks, memory, reports, and audit events from one local Founder console.
- Validate the core behavior with 17 automated tests.

## Quick start

```bash
npm start
```

Open <http://localhost:3333/>. Codex-powered coding tasks additionally require the Codex CLI and ChatGPT sign-in described in the repository README.

## Safety boundary

Codex is an execution provider, not the permission authority. The runtime checks employee identity, active task assignment, task-scoped capability, asset policy, and requested action before protected execution begins.

The current coding executor does not push, merge, deploy, publish, spend money, or access external services. External and consequential actions remain reserved for future scoped connectors and human approval gates.

## Known limitations

- Founder diff review and apply-or-reject controls are not implemented yet.
- Goal planning still uses a deterministic local template rather than an LLM-backed AI CEO.
- Runtime state uses a local JSON file and is not suitable for multi-process production workloads.
- Authentication, durable queues, production-grade isolation, cost controls, and multi-tenant boundaries remain on the roadmap.
